# 账号台账管理 - 效期预警及列表展示优化需求文档

## 1. 需求背景
随着业务发展，账号的合规性要求越来越高，特别是EPR（生产者责任延伸）和欧代（欧洲授权代表）的有效期管理至关重要。为了防止因资质过期导致账号停用或罚款，需要在现有的“账号台账管理”模块中新增效期预警功能。同时，为了提升运营人员处理预警信息的效率，决定对原有的预警展示交互进行升级，采用“左右平铺”的布局方式，实现预警信息的快速预览与便捷处理。

## 2. 目标与范围
1. **新增预警类型**：接入EPR和欧代的“近效期”与“已过期”预警。
2. **优化页面布局**：将原有的弹窗交互改为“左侧账号列表 + 右侧预警详情”的平铺展示结构。
3. **提升处理效率**：支持在列表快速预览最多2条预警，并支持一键查看详情和手动消除预警。

---

## 3. 功能详细说明

### 3.1 新增预警类型定义
系统需每天定时检查账号的EPR和欧代配置信息，触发以下预警：

| 预警类型 | 触发条件 | 预警内容示例 |
| :--- | :--- | :--- |
| **EPR近效期预警** | EPR资质剩余有效期 ≤ 30天 且未过期 | EPR类型=德国包装法，有效期2026-05-20 剩余12天 |
| **EPR过期预警** | EPR资质已过有效期 | EPR类型=法国电气法，有效期2025-12-01 已过期30天 |
| **欧代近效期预警** | 欧代剩余有效期 ≤ 30天 且未过期 | 当前欧代有效期2026-06-01 剩余18天 |
| **欧代过期预警** | 欧代已过有效期 | 当前欧代有效期2025-11-15 已过期46天 |

*(注：原有预警如“FBMM业务员设置错误”等继续保留，与新预警统一管理。)*

### 3.2 页面整体布局
- 页面采用 **左右平铺（Split-pane）** 结构，适配PC宽屏。
- **左侧面板（账号列表）**：占据约 55% 宽度，展示账号基础信息及预警摘要。
- **右侧面板（预警详情）**：占据约 45% 宽度，采用粘性定位（Sticky），随页面滚动始终保持在可视区域内。

### 3.3 左侧：账号列表展示规则
1. **基础列**：来源渠道、账号状态、负责人、操作。
2. **来源渠道列**：
   - 上方显示“渠道名称”（如 `Amazon-Z011665-AU`），并附带一键复制图标。
   - 下方显示该账号的**预警摘要区块**（浅橙色背景块）。
3. **预警摘要区块规则**：
   - 仅当该账号存在预警时显示。
   - 区块内按**预警时间倒序**（最新的在最上面）展示预警类型（带警告图标）。
   - **最多展示 2 条**预警类型。
4. **“详情”按钮逻辑**：
   - 按钮显示在最后一条可见预警的右侧。
   - 如果该账号总预警数 ≤ 2 条，按钮文案为 **“详情”**。
   - 如果该账号总预警数 > 2 条，按钮文案为 **“详情 +N”**（N = 总条数 - 2）。
   - 点击“详情”按钮：
     1. 当前行高亮显示（浅蓝色背景），按钮变为激活态（蓝色边框/文字）。
     2. 右侧面板联动加载该账号的完整预警详情。

### 3.4 右侧：预警详情展示与操作
1. **空状态**：未选择左侧账号时，右侧提示“请在左侧列表中点击‘详情’查看具体预警信息”。
2. **详情展示**：
   - 顶部显示提示信息：“系统每天定时执行检查账号配置；定时检测到问题已修复后自动消除预警，支持点击已确认手动消除”。
   - 下方以表格形式展示该账号的**所有预警明细**。
   - 表格字段：来源渠道（跨列置顶）、预警类型、预警时间、预警内容、操作。
   - 排序规则：按预警时间倒序排列。
3. **手动消除交互**：
   - 操作列提供**“已确认”**按钮。
   - 点击“已确认”并二次确认后，该条预警被消除。
   - **数据联动**：右侧消除预警后，左侧列表的预警摘要区块必须**实时同步更新**（如条数减少、按钮的+N数字变化；若预警全部消除，左侧的预警区块消失）。
   - 若右侧详情中的预警被全部消除，右侧面板显示空状态：“该渠道暂无预警数据”。

## 4. 交互与UI规范
- **色彩规范**：
  - 预警区块背景色：浅橙色（`#fffaf0`）
  - 预警边框/文字色：橙色（`#ffe58f` / `#d46b08`）
  - 选中行高亮色：浅蓝色（`#e6f7ff`）
- **操作反馈**：
  - 点击“已确认”需有浏览器原生的 `confirm` 二次确认弹窗，防止误操作。
  - 复制图标需有 `hover` 状态的透明度变化。

## 5. 阶段与排期建议
- **前端开发**：完成左右平铺布局、预警区块渲染逻辑、+N计算逻辑、左右面板数据联动。
- **后端开发**：增加定时任务，扫描EPR和欧代效期，生成对应的预警数据结构；提供手动消除预警的接口。
- **测试重点**：
  1. 预警条数为1条、2条、3条及以上时，左侧UI和“+N”按钮的显示是否正确。
  2. 左右两侧数据消除时的状态同步是否准确。
  3. 页面向下滚动时，右侧面板的固定效果。
